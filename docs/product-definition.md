# 产品定义

## 已确认范围

Project Standard 是一个常驻 macOS 菜单栏的小应用。点击状态栏图标后打开一个约 320 px 宽的 Popover，不使用完整桌面窗口。

一个项目可以有多个方案。每个方案固定包含七类项目基础：基础 Prompt、规范与 Rules、记忆、项目要求、Skills、Tools 与 MCP、权限与 Hooks。

主界面只显示：当前项目、方案列表、本机接入及开关、检测状态。

首次选择项目时不要求用户预先创建配置。用户可以选择任意项目目录；若目录内没有 `.project-standard`，应用创建一个默认方案和七类基础文件后直接加载。已有规范保持原样；不完整的 `.project-standard` 会明确报错，避免覆盖用户内容。

## 方案交互

每个方案是一行，但有两个明确点击目标：

- 左侧圆形选择器：把该方案设为当前方案，只切换，不打开详情。
- 右侧名称、摘要和数量：打开该方案详情，只查看，不改变当前方案。

详情仍在同一个 Popover 中。七类内容每行显示真实的项目相对路径；点击文件用默认编辑器打开，点击目录在 Finder 中定位。

## 本机接入

接入身份由端、认证方式、Provider/路由、用户级配置来源共同确定。例如以下三项是不同接入，即使都运行在 Codex：

- `Codex · ChatGPT 订阅`
- `Codex · OpenAI API Key`
- `Codex · 公司 LLM Proxy`

用户可针对每个接入应用或取消当前方案。认证或 Provider 配置变化后，应用重新识别接入并校验投影；项目方案源不随账号配置改变。

Codex 通过 App Server 账号事件和生效配置识别当前认证与 `model_provider`。受 App Sandbox 限制时，用户只需通过系统目录选择器授权一次 `.codex`；应用不读取或保存账号邮箱和凭据值。

Smart Work 通过应用 Bundle 识别。DCC 与 Claude Code 通常位于 `~/.local/bin`，应用在沙箱中自动只读识别可执行文件路径和版本，不读取两端的凭据或模型配置，也不要求用户选择隐藏目录。

用户可从“本机接入”右侧的 `＋` 添加自研 Agent。最小配置包含端名称、项目指令文件相对路径和项目 Skills 目录相对路径。自定义端作为独立接入显示，可应用、取消、编辑和删除；启用状态下先关闭再修改路径，避免旧投影失去所有权记录。自定义端只声明可验证的 Prompt、Rules、记忆、项目要求和 Skills，不默认推断 MCP、权限或 Hooks 协议。

## 界面边界

首版不包含完整窗口、侧栏、工作流画布、活动记录、版本管理、适配器矩阵、账号管理或密钥管理。配置编辑通过方案详情中的真实文件入口完成。

## 生效规则

- 每个“项目 + 接入”同一时间只绑定一个方案。切换时先取消原绑定，再应用新方案，避免多个方案竞争同一份端配置。
- 只有七类全部解析、目标内容验证通过且客户端版本在已验证能力矩阵中时显示绿色 `7/7 生效`；其他情况显示准确数量或待复验原因。
- 无法可靠识别账号身份时显示认证类型和配置来源，不推测邮箱或 API Key 所属账号。

## 验收标准

- 方案选择和方案详情是两个独立动作。
- 方案详情显示七类真实路径，且可以打开文件或定位目录。
- 用户可独立应用或取消每个接入。
- 切换账号、认证方式、Provider 或配置文件后，已绑定方案仍可被重新识别和校验。
- 应用不读取、保存或展示凭据值。
